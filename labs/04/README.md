### Задание 1: сортировка дат — **40 баллов**

Пользователь вводит:

1. Целое число `N` — количество дат
   `1 ≤ N ≤ 10`
2. Далее `N` дат.
   Каждая дата вводится в формате:

```txt
day month year
```

Все значения — целые числа.

В базовой части **предполагается, что все введённые даты корректны**.
Проверку корректности реализовывать не требуется.

---

#### Требуется

1. Считать `N` дат.
2. Отсортировать их в **хронологическом порядке** (от самой ранней к самой поздней).
3. Вывести отсортированные даты в том же формате.

#### Рекомендуемая модель данных

```c
typedef struct
{
    int day;
    int month;
    int year;
} Date;
```

#### Правила сравнения дат

Дата `A` раньше даты `B`, если:

- `A.year < B.year`,
  или
- годы равны, но `A.month < B.month`,
  или
- годы и месяцы равны, но `A.day < B.day`.

---

#### Бонус за проверку корректности дат — **10 баллов**

Добавить проверку корректности даты.

Программа должна:

1. Проверять корректность каждой введённой даты.
2. В случае некорректной даты выводить сообщение об ошибке и завершать работу.

##### Требования к проверке

- Месяц должен быть от 1 до 12.
- День должен быть в допустимом диапазоне для данного месяца.
- Учитывать високосные годы.

##### Год является високосным, если:

- делится на 400
  или
- делится на 4, но не делится на 100.

Пример:

- 2000 — високосный
- 1900 — не високосный
- 2024 — високосный

### Задание 2: ближайший населённый пункт — **80 баллов**

На плоской планете есть до 10 населённых пунктов. Каждый имеет целочисленные координаты и название.
Путешественник находится в некоторой точке. Нужно найти ближайший(ие) населённый(ые) пункт(ы) по **Манхеттенскому расстоянию**.

#### Формат входных данных

1. Одно целое число `N` — количество населённых пунктов.
   `1 ≤ N ≤ 10`

2. Далее `N` строк, каждая в формате:

    `X Y Name`, где
   - `X`, `Y` — целые числа
   - `Name` — одно слово длиной **до 20 символов** (без учёта `'\0'`)
3. Последняя строка: координаты пользователя

`Ux Uy`

#### Манхэттенское расстояние

Манхэттенское расстояние (расстояние городских кварталов) — это расстояние между двумя точками,
если двигаться можно только по горизонтали и вертикали.

Для точек `(x1, y1)` и `(x2, y2)` оно вычисляется так:

```txt
|x1 - x2| + |y1 - y2|
```

То есть модуль разницы по X складываем с модулем разницы по Y.

#### Требования к программе

1. Прочитать `N`, затем массив из `N` населённых пунктов.
2. Прочитать координаты пользователя.
3. Найти минимальное расстояние до населённых пунктов.
4. Вывести **все** населённые пункты, у которых это расстояние минимально.
5. Для каждого выведенного пункта вывести:
   - название,
   - координаты,
   - расстояние до пользователя.

---

#### Формат вывода

Свободный, но должен содержать всю информацию. Например:

Если ближайший один:

```txt
Nearest:
TownA (10, 5) distance = 7
```

Если несколько на одинаковом минимуме:

```txt
Nearest:
TownA (10, 5) distance = 7
TownB (8, 6) distance = 7
```

#### Примеры входных и выходных данных

##### Пример 1

Входные данные:

```txt
5
0 0 Alpha
10 5 Beta
-3 4 Gamma
7 -2 Delta
2 3 Epsilon
3 2
```

Выходные данные:

```txt
Nearest:
Epsilon (2, 3) distance = 2
```

Пояснение:

Координаты пользователя: `(3, 2)`

Считаем расстояния:

- Alpha: `|0−3| + |0−2| = 3 + 2 = 5`
- Beta: `|10−3| + |5−2| = 7 + 3 = 10`
- Gamma: `|-3−3| + |4−2| = 6 + 2 = 8`
- Delta: `|7−3| + |-2−2| = 4 + 4 = 8`
- Epsilon: `|2−3| + |3−2| = 1 + 1 = 2`

Минимальное расстояние — **2**.

##### Пример 2

Вход:

```txt
3
0 0 A
2 0 B
1 1 C
1 0
```

Выход:

```txt
Nearest:
A (0, 0) distance = 1
B (2, 0) distance = 1
C (1, 1) distance = 1
```

### Задание 3 - Определение выпуклости многоугольника — **150 баллов**

#### Цель работы

Научиться:

- моделировать геометрические объекты с помощью структур;
- работать с массивами структур;
- разбивать решение на функции;
- реализовывать алгоритмы вычислительной геометрии на целых числах;
- обрабатывать ошибки ввода и некорректные данные.

#### Постановка задачи

На вход программе подаётся число `N`, задающее количество вершин многоугольника, а затем `N` пар целых чисел,
каждая из которых задаёт координаты очередной вершины многоугольника в порядке обхода.

Требуется:

1. считать описание многоугольника;
2. проверить корректность входных данных;
3. определить, является ли данный многоугольник выпуклым;
4. вывести результат.

#### Формат входных данных

Сначала вводится целое число:

```txt
N
```

Затем вводятся `N` строк или `N` пар чисел:

```txt
x1 y1
x2 y2
...
xN yN
```

где:

- $N$ — количество вершин многоугольника;
- $(x_i, y_i)$ — координаты i-й вершины;
- все координаты — целые числа.

#### Требования к обработке ошибок

Программа должна корректно обрабатывать ошибки.

Нужно проверить:

1. удалось ли считать `N`;
2. что `N >= 3`;
3. удалось ли считать все `N` пар координат.

Если входные данные некорректны, программа должна вывести сообщение об ошибке и завершить работу.

Примеры ошибок:

- вместо `N` введён нечисловой текст;
- `N < 3`;
- не удалось считать одну из координат вершины;
- вход закончился раньше времени.

#### Модель данных

Рекомендуется использовать структуры.

##### Точка

```text
Point = (x, y)
```

##### Многоугольник

Многоугольник можно представить как массив точек и число вершин.
Вершины многоугольника должны храниться **в динамической памяти (в куче)**.
Нельзя использовать статический массив фиксированного размера вроде:

```c
Point vertices[100];
```

Количество вершин известно только во время выполнения программы, поэтому память должна выделяться динамически.
То есть структура многоугольника должна содержать:

- указатель на массив точек;
- количество вершин.

Студенты должны реализовать функции для создания и уничтожения многоугольника.

#### Что считать выпуклым многоугольником

В базовой части работы предполагается, что многоугольник **простой**,
то есть его стороны не пересекаются друг с другом, кроме соседних сторон в общей вершине.

Многоугольник считается выпуклым, если при обходе его вершин все повороты происходят в одну сторону:

- либо всегда влево;
- либо всегда вправо.

#### Алгоритм определения выпуклости

##### Шаг 1. Рассмотреть тройки соседних вершин

Для каждой вершины нужно рассмотреть три последовательные точки:

```text
A = vertex[i]
B = vertex[i+1]
C = vertex[i+2]
```

Индексы нужно брать **по модулю `N`**, чтобы после последней вершины снова переходить к первой.

То есть:

- после `vertex[N-1]` идёт `vertex[0]`,
- после `vertex[N]` идёт `vertex[1]`.

##### Шаг 2. Определить направление поворота

Для трёх точек `A(x1, y1)`, `B(x2, y2)`, `C(x3, y3)` вычисляется величина:

```text
cross = (x2 - x1) * (y3 - y2) - (y2 - y1) * (x3 - x2)
```

Это ориентированная площадь параллелограмма, или, что то же самое, знак векторного произведения соседних рёбер.

##### Интерпретация результата

- `cross > 0` — поворот влево;
- `cross < 0` — поворот вправо;
- `cross = 0` — три точки лежат на одной прямой.

##### Шаг 3. Проверить, меняется ли знак

Алгоритм:

1. Обойти все тройки соседних вершин.
2. Для каждой тройки вычислить `cross`.
3. Значения `cross = 0` можно пропускать.
4. Запомнить знак первого ненулевого `cross`.
5. Если позже встретится ненулевой `cross` противоположного знака, то многоугольник **невыпуклый**.
6. Если все ненулевые `cross` имеют один и тот же знак, то многоугольник **выпуклый**.

#### Почему этот алгоритм работает

Если при обходе многоугольника все повороты происходят только в одну сторону,
значит граница многоугольника всё время "заворачивает" одинаково, без вдавленных углов.

Если хотя бы один поворот отличается по направлению, значит у многоугольника есть вогнутая часть, и он невыпуклый.

#### Формат выходных данных

Если многоугольник выпуклый:

```text
Convex
```

Если многоугольник невыпуклый:

```text
Not convex
```

Если обнаружена ошибка ввода:

```text
Input error
```

или другое понятное сообщение об ошибке.

---

#### Пример 1

##### Вход

```txt
4
0 0
4 0
4 3
0 3
```

##### Выход

```txt
Convex
```

#### Пример 2

##### Вход

```txt
5
0 0
4 0
2 1
4 3
0 3
```

##### Выход

```txt
Not convex
```

#### Бонус за определение самопересечения — **50 баллов**

В базовой части предполагается, что многоугольник простой, то есть без самопересечений.
Если вы хотите сделать более полную программу, добавьте проверку на самопересечение.

Если многоугольник самопересекающийся, программа должна уметь это определить отдельно.

Например, возможен такой вывод:

```txt
Self-intersecting
```

##### Идея алгоритма

Многоугольник самопересекается, если найдётся хотя бы одна пара **несоседних** сторон, которые пересекаются.

###### Шаг 1. Построить все стороны

Стороны многоугольника:

- от `vertex[0]` к `vertex[1]`,
- от `vertex[1]` к `vertex[2]`,
- ...
- от `vertex[N-1]` к `vertex[0]`.

###### Шаг 2. Проверить все пары сторон

Нужно проверить все пары сторон, которые не являются соседними.

Соседние стороны имеют общую вершину, их пересечение допустимо и не считается самопересечением.

Также первая и последняя стороны тоже считаются соседними.

###### Алгоритм проверки пересечения двух отрезков

Пусть есть два отрезка:

- `AB`
- `CD`

Сначала вычисляются четыре ориентации:

```txt
orient(A, B, C)
orient(A, B, D)
orient(C, D, A)
orient(C, D, B)
```

где

```txt
orient(P, Q, R) = (Qx - Px) * (Ry - Py) - (Qy - Py) * (Rx - Px)
```

###### Основной случай пересечения

Если точки `C` и `D` лежат по разные стороны от прямой `AB`,
и одновременно точки `A` и `B` лежат по разные стороны от прямой `CD`, то отрезки пересекаются.

То есть:

- `orient(A,B,C)` и `orient(A,B,D)` имеют разные знаки;
- `orient(C,D,A)` и `orient(C,D,B)` имеют разные знаки.

###### Коллинеарный случай

Если одна из ориентаций равна нулю, точки лежат на одной прямой.
Тогда дополнительно нужно проверить, лежит ли точка на отрезке.

Точка `P` лежит на отрезке `AB`, если одновременно:

```te\xt
min(Ax, Bx) <= Px <= max(Ax, Bx)
min(Ay, By) <= Py <= max(Ay, By)
```

Если найдена хотя бы одна пара несоседних сторон, которые пересекаются, многоугольник нужно считать самопересекающимся.

#### Бонус за вычисление площади выпуклого многоугольника — **20 баллов**

Если многоугольник выпуклый, программа должна дополнительно вывести его площадь.

##### Формула площади

Для многоугольника с вершинами

```txt
(x0, y0), (x1, y1), ..., (xN-1, yN-1)
```

площадь вычисляется по формуле Гаусса:

$$
S = 1/2 * | (x_0*y_1 + x_1*y_2 + ... + x_{N-1}*y_0) - (y_0*x_1 + y_1*x_2 + ... + y_{N-1}*x_0) |
$$

Удобнее записать в виде суммы:

```txt
sum = 0
для i от 0 до N-1:
    j = (i + 1) mod N
    sum += xi * yj - yi * xj

S = |sum| / 2
```

##### Важное замечание

Если использовать только целые числа, то значение `sum` будет целым, а площадь может оказаться:

- либо целым числом,
- либо числом с `.5`.

Поэтому можно хранить отдельно числитель `|sum|` и помнить,
что реальная площадь равна `|sum| / 2` и при выводе добавлять `.5`, если `sum` — нечётная

Например:

- если `|sum| = 12`, то площадь `6`;
- если `|sum| = 13`, то площадь `6.5`.
