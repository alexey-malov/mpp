## Задания

### Задание 1. Мигающий светодиод с изменяемой частотой — **50 баллов**

#### Цель работы

Познакомиться с:

- цифровыми выводами микроконтроллера (GPIO),
- управлением внешними устройствами,
- работой с кнопками,
- программной обработкой ввода,
- использованием встроенных pull-up резисторов.

В ходе работы необходимо собрать простую электронную схему на базе Arduino Uno/Nano и написать программу управления светодиодом.

#### Условие задания

Необходимо собрать схему, содержащую:

- один светодиод,
- одну кнопку.

Программа должна:

1. мигать светодиодом;
2. изменять частоту мигания при нажатии кнопки.

Например:

- первое нажатие — медленное мигание;
- второе — более быстрое;
- третье — ещё быстрее;
- затем цикл повторяется.

Конкретные значения задержек студент выбирает самостоятельно.

#### Требования к программе

Программа должна:

- использовать GPIO микроконтроллера;
- корректно настраивать выводы на input/output;
- использовать встроенный pull-up резистор для кнопки;
- работать в бесконечном цикле;
- корректно обрабатывать нажатия кнопки.

#### Требования к схеме

##### Подключение светодиода

Необходимо:

- подключить анод светодиода к цифровому выводу Arduino через резистор;
- подключить катод светодиода к GND.

Рекомендуемое сопротивление резистора:
220–330 Ом.

Пример:

```text
Arduino pin ---- resistor ---- LED ---- GND
```

##### Подключение кнопки

Необходимо:

- подключить одну сторону кнопки к GND;
- подключить другую сторону кнопки к цифровому входу Arduino.

В программе следует включить встроенный pull-up резистор.

Пример:

```text
Arduino pin ---- button ---- GND
```

В этом случае:

- в ненажатом состоянии вход имеет уровень HIGH;
- при нажатии кнопки вход переходит в состояние LOW.

#### Ограничения

Не рекомендуется использовать функцию `delay` для обработки кнопки,
так как во время выполнения задержки микроконтроллер не может реагировать на другие события.
Такая задержка блокирует выполнение программы и ухудшает отзывчивость системы.
Рекомендуется организовать программу таким образом,
чтобы проверка состояния кнопки выполнялась регулярно без длительных блокирующих ожиданий.

- использовать функцию `delay()` для обработки кнопки;
- использовать глобальные задержки большой длительности, полностью блокирующие обработку ввода.

Рекомендуется реализовать обработку кнопки таким образом,
чтобы программа продолжала корректно реагировать на нажатия во время работы.

##### Что необходимо продемонстрировать при защите

Студент должен:

- объяснить принцип работы GPIO;
- показать схему подключения;
- объяснить назначение pull-up резистора;
- объяснить принцип работы программы;
- продемонстрировать работу устройства;
- объяснить, как производится обработка нажатия кнопки.

#### Бонус Антидребезг (debouncing) — **10 баллов**

Реализовать программную защиту от дребезга контактов кнопки.

При механическом нажатии кнопки контакты могут кратковременно многократно замыкаться и размыкаться,
создавая серию ложных сигналов (дребезг контактов).

Для программной защиты от дребезга можно после обнаружения изменения состояния кнопки
подождать небольшой интервал времени (10-15 мс) и повторно проверить состояние входа.
Изменение состояния следует считать корректным только в том случае, если сигнал остаётся стабильным в течение этого времени.

#### Бонус управление через interrupts — **20 баллов**

Реализовать обработку кнопки с использованием внешних прерываний.

#### Бонус использование timer interrupt — **20 баллов**

Реализовать мигание светодиода без использования `delay()`.

### Задание 2 — командный интерпретатор через UART — **100 баллов**

#### Цель работы

Познакомиться с:

- интерфейсом UART,
- последовательной передачей данных,
- обработкой строк,
- разбором команд,
- организацией простого текстового интерфейса управления устройством.

В ходе работы необходимо реализовать командный интерпретатор, взаимодействующий с пользователем через UART.

#### Условие задания

Необходимо написать программу для Arduino Uno/Nano, реализующую текстовый командный интерфейс через UART.

После запуска программа должна принимать команды от пользователя через последовательный порт
и выполнять соответствующие действия.

Взаимодействие с программой осуществляется через Serial Monitor или любой UART-терминал.

#### Требования к программе

Программа должна:

- принимать строки через UART;
- разбирать введённую команду;
- выполнять действие, соответствующее команде;
- выводить результат выполнения обратно через UART;
- работать в бесконечном цикле.

#### Аппаратная часть

Необходимо собрать схему, содержащую:

- минимум один светодиод,
- минимум одну кнопку.

Рекомендуется:

- подключить светодиод через резистор 220–330 Ом к одному из цифровых выводов Arduino;
- подключить кнопку между GPIO-входом и GND;
- использовать встроенный pull-up резистор.

#### Обязательные команды

Программа должна поддерживать как минимум следующие команды:

##### Управление светодиодом

###### Включение светодиода

```text
led on
```

###### Выключение светодиода

```text
led off
```

---

##### Получение состояния кнопки

```text
button
```

Программа должна вывести текущее состояние кнопки.

##### Справка

```text
help
```

Программа должна вывести список поддерживаемых команд.

#### Обработка ввода

Команды вводятся в текстовом виде и завершаются символом перевода строки.

Программа должна:

- корректно обрабатывать неизвестные команды;
- игнорировать лишние пробелы;
- не завершать работу при ошибках ввода.

#### Ограничения

Запрещается:

- использовать динамическое выделение памяти (`malloc`, `new`);
- хранить неограниченно длинные строки;
- использовать блокирующие задержки большой длительности.

Рекомендуется использовать:

- фиксированный буфер для приёма строки;
- конечный автомат или простой парсер команд.

#### Что необходимо продемонстрировать при защите

Студент должен:

- показать собранную схему;
- продемонстрировать работу командного интерфейса;
- объяснить принцип работы UART;
- объяснить организацию обработки строк;
- объяснить структуру программы;
- показать обработку ошибочного ввода;
- объяснить, каким образом реализован разбор команд.

#### Бонус — аргументы команд — **20 баллов**

Добавить поддержку параметров.

Например:

```text
blink 200
```

где число задаёт период мигания светодиода в миллисекундах.

#### Бонус — таблица команд — **20 баллов**

Реализовать интерпретатор через таблицу структур:

```c
typedef struct {
    const char* name;
    void (*handler)(const char* args);
} Command;
```

#### Бонус — обработка UART через interrupts — **30 баллов**

Реализовать приём символов с использованием UART interrupts.

#### Бонус — несколько устройств — **30 баллов**

Добавить управление несколькими светодиодами или другими GPIO.

### Задание3 — генератор звука — **120 баллов**

#### Цель работы

Познакомиться с:

- аппаратными таймерами микроконтроллера,
- генерацией периодических сигналов,
- PWM,
- управлением частотой сигнала,
- взаимодействием программы с внешними устройствами.

В ходе работы необходимо собрать простую схему и реализовать программный генератор звуковых сигналов.

#### Условие задания

Необходимо собрать схему на базе Arduino Uno/Nano, содержащую:

- пьезоизлучатель (buzzer) или небольшой динамик.

Программа должна генерировать звуковые сигналы различной частоты.

Минимальные требования:

- воспроизведение как минимум трёх различных звуковых частот;
- возможность переключения между частотами;
- непрерывная работа программы.

Способ переключения частот студент выбирает самостоятельно.

Например, можно использовать:

- кнопки;
- UART-команды;
- потенциометр;
- автоматическое циклическое переключение.

---

#### Требования к схеме

##### Подключение buzzer

Рекомендуется использовать пьезоизлучатель.

Пример подключения:

```text
Arduino pin ---- buzzer ---- GND
```

Для некоторых типов динамиков может потребоваться резистор или транзисторный ключ.

##### Требования к программе

Программа должна:

- генерировать прямоугольный сигнал на GPIO;
- изменять частоту сигнала;
- использовать таймеры или PWM микроконтроллера;
- работать в бесконечном цикле.

#### Подсказки

##### Как формируется звук

Пьезоизлучатель воспроизводит звук, если на него подавать быстро изменяющийся электрический сигнал.

Например:

```text
HIGH → LOW → HIGH → LOW → ...
```

Частота переключения определяет высоту звука.

##### Как получить сигнал нужной частоты

Если необходимо получить сигнал частоты `f`, то вывод должен переключаться с периодом:

```text
T = 1 / f
```

Поскольку для одного полного периода требуется переключение HIGH → LOW → HIGH,
изменение состояния вывода должно происходить каждые:

```text
T / 2
```

##### Возможные способы реализации

###### 1. Программное переключение GPIO

Например:

```c
PORTB ^= (1 << PB5);
```

с последующей задержкой.

###### 2. Использование timer interrupts

Таймер может периодически вызывать ISR, внутри которого переключается состояние вывода.

Это более правильный способ реализации.

###### 3. Использование hardware PWM

Некоторые таймеры AVR могут автоматически генерировать периодический сигнал без постоянного участия CPU.

#### Ограничения

Запрещается:

- использовать слишком большие блокирующие задержки;
- генерировать сигнал исключительно вручную внутри длинного busy-wait цикла.

Рекомендуется использовать:

- timer interrupts;
- PWM;
- аппаратные таймеры AVR.

#### Что необходимо продемонстрировать при защите

Студент должен:

- показать собранную схему;
- продемонстрировать генерацию различных частот;
- объяснить принцип формирования звука;
- объяснить связь частоты сигнала и высоты звука;
- объяснить принцип работы таймера или PWM;
- объяснить организацию программы.

#### Бонус — проигрывание мелодии — **20 баллов**

Реализовать воспроизведение некоторой узнаваемой мелодии длиной не менее 20-30 нот.

#### Бонус — управление через UART — **30 баллов**

Добавить команды проигрывания звуков заданной частоты и длительности (в мс)

```text
tone 440 300
tone 880 200
stop
```

##### Бонус — использование timer compare interrupts — **30 баллов**

Полностью отказаться от `delay()` и реализовать генерацию сигнала через аппаратный таймер.
