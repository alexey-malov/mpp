## Задания

### Задание 1: RLE-сжатие и распаковка файлов — **100 баллов**

#### 🎯 Цель работы

Освоить работу с файловым вводом-выводом в языке C, включая:

- чтение и запись бинарных данных
- обработку потоков
- проектирование простого формата хранения данных

#### Постановка задачи

Необходимо реализовать программу **rle**, которая поддерживает два режима работы:

##### Сжатие файла

```bash
rle -compress <input-file-name> <output-file-name>
```

Программа должна:

- открыть входной файл для чтения
- открыть выходной файл для записи
- выполнить сжатие данных алгоритмом RLE
- записать результат в выходной файл

##### Распаковка файла

```bash
rle -decompress <input-file-name> <output-file-name>
```

Программа должна:

- открыть входной файл (сжатый)
- восстановить исходные данные
- записать результат в выходной файл

#### Формат сжатых данных (базовый вариант)

Сжатие выполняется по алгоритму **Run-Length Encoding (RLE)**.

Повторяющиеся байты кодируются парами:

```text
[count][value]
```

где:

- `count` — количество повторений байта
- `value` — значение байта

##### 📌 Пример

```text
AAAA → [4][A]
BBBBB → [5][B]
```

#### Ограничение

Значение `count` хранится в одном байте (`uint8_t`), поэтому:

```text
0 ≤ count ≤ 255
```

Если длина последовательности превышает 255, она должна разбиваться:

```text
AAAA... (300 раз) → [255][A] [45][A]
```

#### Требования к реализации

##### Обязательные требования

- использовать **бинарный ввод-вывод** (`fread`, `fwrite`)
- корректно обрабатывать ошибки:

  - открытие файлов
  - чтение/запись
  - закрытие файлов
- программа должна работать с **произвольными бинарными файлами**, а не только с текстом
- не загружать весь файл в память — обрабатывать поток последовательно

#### Ожидаемое поведение

- сжатие и последующая распаковка должны восстанавливать **точно исходные данные**
- программа должна корректно работать с:

  - пустыми файлами
  - файлами из одного байта
  - файлами без повторяющихся последовательностей

#### Бонусное задание (улучшение сжатия): **+50 баллов**

Базовый RLE плохо сжимает данные без повторов. Требуется реализовать улучшенный формат.

##### Новый формат кодирования

###### Повторяющиеся байты

```text
[count][value]
```

- `count ≥ 0`
- байт повторяется **count + 2 раз**

Пример:

```text
[2, 'B'] → BBBB
```

###### Неповторяющиеся последовательности

```text
[count][b1][b2]...[bN]
```

- `count < 0`
- далее следует `|count|` байтов, которые записываются **без изменений**

Пример:

```text
[-3, 'A', 'B', 'C'] → ABC
```

##### Пример

Исходные данные:

```text
AABCD
```

Сжатие:

```text
[0, 'A', -3, 'B', 'C', 'D']
```

##### Требования к бонусному заданию

- корректно обрабатывать границы последовательностей
- выбирать оптимальное представление (повтор или «сырой блок»)
- обеспечить корректную распаковку

#### Результат

В результате выполнения работы студент должен:

- уметь работать с бинарными файлами
- понимать различие между представлением и интерпретацией данных
- уметь проектировать простой файловый формат
- реализовать симметричные алгоритмы кодирования и декодирования

### Задание 2: обработка растровых изображений BMP — **80 баллов**

#### Цель работы

Закрепить навыки работы с бинарными файлами на языке C, научиться:

- читать и записывать данные в заданном бинарном формате;
- работать со структурами и побайтовым представлением данных;
- учитывать выравнивание данных в файле;
- проектировать переносимую программу, корректно работающую на платформах с разным порядком байтов.

#### Постановка задачи

Необходимо написать программу **transform-bmp** на языке C.

Программа должна принимать из командной строки:

1. имя входного файла;
2. имя выходного файла;
3. название операции преобразования.

Формат запуска программы:

```bash
transform-bmp <input-file-name> <output-file-name> <operation>
```

Пример:

```bash
transform-bmp input.bmp output.bmp rotate_cw
```

---

#### Требования к программе

Программа должна:

1. открыть входной файл;
2. загрузить изображение из файла формата **BMP**;
3. поддерживать **только BMP с глубиной цвета 24 bits per pixel**;
4. выполнить указанную операцию преобразования;
5. записать результат в выходной BMP-файл.

#### Поддерживаемые операции

Необходимо реализовать как минимум **одну** операцию. Реализация нескольких операций даёт дополнительные баллы.

##### Обязательные/дополнительные операции (каждая операция: **+20 баллов**)

- `rotate_cw` — повернуть изображение на 90 градусов по часовой стрелке;
- `flip_h` — отразить изображение по горизонтали (слева направо);
- `flip_v` — отразить изображение по вертикали (сверху вниз);
- `invert` — инвертировать цвет каждого пикселя:
  - новая компонента вычисляется как `255 - old`;
- `lighten` — увеличить яркость на 25% с насыщением:
  - значение каждой компоненты умножается на `1.25`;
  - если результат больше `255`, нужно записать `255`.

#### Ограничения и условия

##### 1. Поддерживаемый формат

Программа должна поддерживать только несжатые BMP-файлы:

- глубина цвета: **24 bpp**;
- по 3 байта на пиксель;
- без палитры;
- без сжатия.

Если файл не соответствует этим условиям, программа должна сообщить об ошибке.

##### 2. Переносимость

Программа должна корректно работать:

- на **little-endian** платформах;
- на **big-endian** платформах.

Это означает, что нельзя просто читать заголовки BMP как структуры из файла без учёта порядка байтов.
Все многобайтовые числовые поля BMP-файла должны интерпретироваться в формате **little-endian** независимо от архитектуры компьютера.

##### 3. Выравнивание строк изображения

Нужно учитывать, что в BMP-файле каждая строка пиксельных данных выравнивается до длины, кратной 4 байтам.

Если ширина изображения равна `width`, то длина строки пиксельных данных без выравнивания равна:

```text
width * 3
```

Число байтов в строке с учётом выравнивания вычисляется как:

```text
row_size = ((width * 3 + 3) / 4) * 4
```

Необходимо корректно обрабатывать padding-байты в конце каждой строки.

##### Важно

Обязательно протестировать программу на изображениях, у которых ширина **не кратна 4**.

#### Требования к реализации

##### Программа должна:

- использовать бинарный ввод-вывод (`fread`, `fwrite`);
- проверять ошибки:

  - открытия файлов;
  - чтения;
  - записи;
  - закрытия файлов;
- корректно выделять и освобождать память;
- не изменять входной файл;
- формировать корректный выходной BMP-файл.

#### Обработка ошибок

Программа должна корректно обрабатывать как минимум следующие ситуации:

- неверное число аргументов командной строки;
- неизвестное имя операции;
- файл не удалось открыть;
- входной файл не является BMP;
- неподдерживаемая глубина цвета;
- неподдерживаемый формат BMP;
- ошибки чтения и записи.

При возникновении ошибки программа должна вывести понятное сообщение в `stderr` и завершиться с ненулевым кодом возврата.

#### Рекомендуемая структура решения

Рекомендуется выделить отдельные части программы:

- чтение и проверка заголовков BMP;
- загрузка пиксельных данных;
- функции преобразования изображения;
- запись нового BMP-файла;
- функции для чтения и записи little-endian чисел.

#### Минимальные тесты

Рекомендуется проверить программу на следующих случаях:

1. маленькое изображение 2×2;
2. изображение, ширина которого не кратна 4;
3. изображение, у которого ширина и высота различны;
4. поворот изображения;
5. отражение по горизонтали и вертикали;
6. инверсия цвета;
7. увеличение яркости с насыщением.

#### Методическое замечание

В этой работе BMP-файл следует рассматривать не как «картинку», а как строго определённую последовательность байтов, состоящую из:

- заголовков;
- пиксельных данных;
- padding-байтов.

Главная задача — корректно интерпретировать и сформировать этот бинарный формат.

Вот компактная и практичная памятка — её удобно дать студентам как «шпаргалку» 👇

#### Структура BMP (24 bpp)

##### 📦 Общая структура файла

BMP-файл состоит из трёх частей:

```text
[FILE HEADER][DIB HEADER][PIXEL DATA]
```

---

##### 1. FILE HEADER (14 байт) — заголовок файла

| Смещение | Размер | Поле        | Описание                |
| -------- | ------ | ----------- | ----------------------- |
| 0        | 2      | bfType      | Сигнатура: `'BM'`       |
| 2        | 4      | bfSize      | Размер файла (в байтах) |
| 6        | 2      | bfReserved1 | 0                       |
| 8        | 2      | bfReserved2 | 0                       |
| 10       | 4      | bfOffBits   | Смещение до пикселей    |

---

##### 2. DIB HEADER (BITMAPINFOHEADER, 40 байт) — заголовок растровых данных

| Смещение | Размер | Поле            | Описание              |
| -------- | ------ | --------------- | --------------------- |
| 14       | 4      | biSize          | Размер заголовка (40) |
| 18       | 4      | biWidth         | Ширина (в пикселях)   |
| 22       | 4      | biHeight        | Высота (в пикселях).  |
| 26       | 2      | biPlanes        | Всегда 1              |
| 28       | 2      | biBitCount      | 24 (важно!)           |
| 30       | 4      | biCompression   | 0 (без сжатия)        |
| 34       | 4      | biSizeImage     | Размер пикселей       |
| 38       | 4      | biXPelsPerMeter | можно 0               |
| 42       | 4      | biYPelsPerMeter | можно 0               |
| 46       | 4      | biClrUsed       | 0                     |
| 50       | 4      | biClrImportant  | 0                     |

---

##### 3. PIXEL DATA (пиксели)

###### Формат пикселя (24 bpp)

```text
B G R   (3 байта на пиксель)
```

Порядок: **BGR**, не RGB!

##### Выравнивание строк (очень важно!)

Каждая строка выравнивается до 4 байт:

```text
row_size = ((width * 3 + 3) / 4) * 4
```

- `width * 3` — реальные пиксели
- остаток — padding (заполняется нулями)

##### Порядок строк (важно)

По умолчанию BMP хранит изображение **снизу вверх**:

- Первая строка в файле = нижняя строка изображения.
- Если высота (поле biHeight) отрицательная, то первая строка в файле - верхняя строка изображения.

##### Endianness

Все числовые поля хранятся в little-endian формате

На big-endian машинах нужно явно преобразовывать

##### Минимальные проверки файла

Перед обработкой убедиться:

```text
bfType == 'BM'
biBitCount == 24
biCompression == 0
```

##### Ключевые формулы

###### Размер строки:

```text
row_size = ((width * 3 + 3) / 4) * 4
```

###### Размер изображения:

```text
image_size = row_size * height
```

##### Главное

```text
BMP = заголовки + сырые байты пикселей + padding
```

- нет сжатия
- нет сложных структур
- всё определяется строго по байтам

### Задание 3: поиск товаров в CSV-файле — **70 баллов**

#### 🎯 Цель работы

Закрепить навыки работы с текстовыми файлами и потоками в языке C:

- чтение строк из файла (`fgets`);
- разбор CSV-строк;
- работа со стандартными потоками (`stdin`, `stdout`);
- обработка пользовательского ввода;
- работа со строками (`strstr`, `strcmp`, и др.).

#### Постановка задачи

Необходимо написать программу на языке C, которая выполняет поиск товаров в CSV-файле по подстроке.

#### Формат запуска программы

```bash
program <input-file-name>
```

где:  `<input-file-name>` — имя CSV-файла с данными о товарах.

---

#### Формат входного файла

Каждая строка файла содержит описание одного товара:

```text
<name>,<quantity>,<price>
```

Пример:

```text
Apple,10,2.5
Banana,5,1.2
Pineapple,3,4.0
```

где:

- `name` — название товара (строка);
- `quantity` — количество (целое число);
- `price` — цена за единицу (вещественное число).

---

#### Поведение программы

После запуска программа должна:

1. открыть файл;
2. перейти в цикл обработки пользовательского ввода;
3. запрашивать у пользователя строку поиска через `stdin`.

---

##### 📌 Поиск

Для каждой введённой строки:

- найти все товары, в названии которых **содержится указанная подстрока**;
- вывести найденные товары в `stdout` в исходном формате:

```text
<name>,<quantity>,<price>
```

##### 💰 Дополнительно

После вывода всех найденных товаров программа должна вывести:

```text
Total cost: <value>
```

где:

```text
value = сумма (quantity * price) по всем найденным товарам
```

##### Повтор ввода

- программа должна продолжать работу, запрашивая новые строки поиска;
- если пользователь вводит **пустую строку**, программа должна завершиться.

##### Пример работы

```text
> program products.csv
Enter search string: apple
Apple,10,2.5

Total cost: 37.0

Enter search string: ban
Banana,5,1.2
Total cost: 6.0

Enter search string:

```

#### Требования к реализации

Программа должна:

- корректно открывать файл и проверять ошибки;
- использовать `fgets` для чтения строк;
- корректно обрабатывать строки произвольной длины (в разумных пределах);
- игнорировать символ перевода строки при вводе;
- использовать безопасные функции преобразования (`strtol`, `strtod` предпочтительно);
- корректно обрабатывать пустые строки;
- не модифицировать входной файл.

#### Обработка ошибок

Программа должна обрабатывать:

- отсутствие аргумента командной строки;
- невозможность открыть файл;
- некорректный формат строки в файле.

При ошибке выводить сообщение в `stderr` и завершать работу.

CSV-файл в данной задаче рассматривается как текстовое представление данных.
Программа должна самостоятельно интерпретировать строки файла и преобразовывать их в значения типов `int` и `double`.
